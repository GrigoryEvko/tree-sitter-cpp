# The files whose tree DEPENDS on the dedupe of the parse stack, over the full corpus.
# Refer to xtask/src/dedupe.rs and to `stack_node_add_link` of vendor/tree-sitter/src/stack.c.
#
# THE COUNT IS NOT A COUNT OF DEFECTS. IT IS A COUNT OF TREES THAT NO RULE DECIDES. The
# dedupe drops one of two readings of one span without a comparison of the children, and the
# reading that survives comes from the order of the links. In the largest family of this
# population, 2,225 files of `sizeof(NAME[i])`, THE DEFAULT READING IS CORRECT IN 2,021,
# because the name is an object and not a type. A commit that drives this count toward zero
# is as likely to make the trees worse as better.
#
# WHAT THIS FILE PROMISES: a file that joins the population fails the check. A file that
# leaves it does not, so a repair never fails its own check.
# WHAT IT DOES NOT PROMISE: nothing about the SITE. A file that leaves the population at one
# site and joins it at another keeps its row, and no check here sees that.
#
# A COUNT MEASURED AGAINST A STALE BASELINE IS A FINDING AND NOT A BASELINE. integrate.sh
# writes this file again at each landing whose gate found falls, so a fall of the next gate
# belongs to the commits under that gate. The first run of this check read 136 falls against
# a baseline of an earlier master, and 124 of those belonged to one landing that nobody had
# connected to this class.
# A FALL IS WORTH ATTRIBUTING. A file leaves this population when a rule DECIDES its tree,
# and also when a reading is REMOVED. The two look the same here, and only the commit that
# caused the fall knows which one it made.
#
# 2815 files, of the corpus of the fork master.
